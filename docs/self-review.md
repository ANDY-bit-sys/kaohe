# 考核前的讲解练习

先对着作品回答，再展开参考。这里是学习材料，不表示本人已经完成复核。

1. `git commit` 与 `git push` 有什么区别？
2. 贪吃蛇没吃到食物时，为什么删掉数组最后一格？
3. AI 找到最短食物路线后，为什么还要检查蛇尾？
4. 主题为什么刷新后还在？
5. RC 的 1 ms 时间常数是不是“电容充满的时间”？
6. 戴维南等效为什么要接上相同负载再比较？
7. NMOS 输入升高时，输出为什么下降？
8. PySpice 与 Ngspice 各自做什么？

<details><summary>展开参考思路</summary>

1. commit 把修改保存成本地历史；push 把本地提交上传到远程仓库。
2. 加入新蛇头、删除旧蛇尾，长度不变但位置前移；吃到食物时保留尾巴，长度增加。
3. 最短路可能把身体围住。代码模拟吃完之后的身体，检查头尾可达及巡航顺序；不安全时沿闭合路线继续。
4. 程序把选择保存到 localStorage，页面加载时读取并应用。
5. 不是。对从零开始的理想阶跃，经过一个时间常数，电容电压达到最终变化量的约 63.2%。
6. 我们要验证端口对外表现等效，所以负载必须相同；等效不要求内部电流和功耗都相同。
7. 栅压升高导致漏极电流增加，Rd 压降增加，输出电压 VDD−ID·Rd 随之下降。
8. PySpice 用 Python 描述电路和发出仿真指令；Ngspice 负责计算电路。图表是将结果可视化。

</details>

## 动手复核

- 打开游戏，完成一次转向、暂停、主题切换；启动 AI 并观察吃到 15 个。
- 在终端运行 `git status`、`git log --oneline`，指出一次确实改变游戏功能的提交。
- 运行 `tests/pyspice-save-repro.py`，亲眼看到原错误与修复结果，再用自己的话说明原因。
- 看着电路图自己重画 RC、戴维南和 MOS 电路，标清接线；独立代入数值计算，并与 README 对照。
- 电路推导遇到不懂的步骤先学习：尤其是 MOS 的 K 定义、静态工作点与小信号增益，不能只背最终数值。
- 在 GitHub 安全设置确认两步验证；将恢复码保管在个人安全位置，不放进公开仓库。
- 把仓库链接填写到协会指定收集表，核实提交成功和截止日期。
